# Momiji 수동 호환성 검증

시스템 적용은 비공개 런타임 심볼에 의존하므로 아래 검증을 릴리스마다 macOS 15 최신 버전과 macOS 26 최신 버전에서 각각 수행합니다. Apple Silicon 실기기와 Intel 실기기 또는 Intel CI 빌드를 모두 확인합니다.

## 사전 조건

- 테스트에 사용할 커서 fixture는 직접 생성했거나 재배포·사용 권한이 있는 파일만 사용합니다.
- 현재 활성 테마와 로그인 항목 상태를 기록합니다.
- 시스템 적용 테스트 중 앱/테스트가 종료되더라도 기본값 복원을 실행할 수 있도록 Momiji를 열어 둡니다.
- 자동화된 실제 적용 테스트는 `MOMIJI_RUN_SYSTEM_INTEGRATION_TESTS=1`을 명시한 경우에만 실행하고, 모든 경로에서 `defer`로 `restoreDefaults()`를 호출합니다.

## 기능 시나리오

1. PNG CUR, DIB 1/4/8/24/32비트 CUR, 다중 해상도 CUR와 순차/`seq`/가변 `rate` ANI가 포함된 폴더를 드롭합니다.
2. INF 역할이 파일명 추론보다 우선하는지, 역할 충돌은 저장 버튼을 막는지, 미매핑·손상 파일은 해당 행에만 경고되는지 확인합니다.
3. 핫스폿을 드래그하고 논리 크기·재생 속도·역할을 바꾼 뒤 미리보기의 이미지, 순서, 속도를 비교합니다.
4. 저장 후 `.momiji`로 내보내고 새 라이브러리에 다시 가져와 manifest와 PNG 프레임 손실이 없는지 비교합니다.
5. 전체 테마와 일부 역할만 있는 테마를 차례로 적용하여 이전 테마의 누락 역할이 남지 않는지 확인합니다.
6. 의도적으로 적용 실패를 유발한 fixture에서 이전 활성 테마 또는 시스템 기본값으로 완전히 롤백되는지 확인합니다.
7. 기본값 복원을 누르고 모든 Momiji 사용자 지정 역할이 사라지는지 확인합니다.

## 지속 적용

1. 설정에서 지속 적용을 켭니다. 승인이 필요한 경우 안내 버튼이 로그인 항목 시스템 설정을 여는지 확인합니다.
2. 로그아웃/로그인, 절전/복귀, 빠른 사용자 전환 후 활성 테마가 다시 적용되는지 확인합니다.
3. 지속 적용을 끈 뒤 `MomijiHelper` 프로세스가 남지 않고 이후 이벤트에서 재실행되지 않는지 확인합니다.

## 로케일 및 배포

- 시스템 언어를 한국어와 영어로 각각 설정하고 가져오기 → 검토 → 편집 → 저장 → 적용 → 복원 흐름을 확인합니다.
- `lipo -archs`로 메인 앱과 내장 helper가 모두 `arm64 x86_64`인지 확인합니다.
- `codesign --verify --deep --strict`, `spctl --assess`, `xcrun stapler validate`를 DMG와 앱에 맞게 실행합니다.
- 네트워크 요청이 없고 관리자 인증 대화상자가 나타나지 않는지 확인합니다.

검증이 끝나면 로그인 항목을 원래 상태로 돌리고 반드시 **기본값 복원**을 실행합니다.
